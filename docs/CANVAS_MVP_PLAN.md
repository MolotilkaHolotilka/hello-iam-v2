## Шаг 1. Убрать лишнее с главной → страница Import

**Что делаем:**  
Главная страница станет «студией» для работы с шаблоном. Всё старое и техническое уезжает на отдельную страницу **Import**.

**Убираем с главной:**
- выбор `.json` файла с диска;
- ручной ввод путей к картинкам (`templates/.../images/...`).

**Переносим на `/import.html`:**
- загрузка JSON файла;
- подпись «какой файл выбран»;
- связь с тем же контентом, что видит рендер (через `sessionStorage`, как сейчас).

**Зачем:**  
Чтобы основной экран не путал — там только визуальная работа, а «подложить файл с диска» остаётся для продвинутых сценариев.

**Готово когда:** открыл главную — нет file picker; открыл Import — file picker есть и контент подхватывается для рендера.

## Два режима работы: когда CSS, когда props

| Действие | Что редактируешь | Как часто |
|----------|------------------|-----------|
| **Новая серия карточек** (новый layout) | CSS → Import (шаги 5–6) **один раз** | Редко |
| **Каждый пост / ролик** | `content.json` (текст, цвета, картинки) в UI | Постоянно |
| **Код шаблона** | `template.tsx` | Почти никогда (один базовый шаблон) |

**Сейчас:** lavash, dolma, matsun, khachkar **не имеют своего tsx** — все ссылаются на `green-plate-intro/template.tsx`. Меняешь только `content.example.json` и картинки. **TSX на каждую серию не трогаем.**

CSS не «каждый раз перед рендером» — только **при создании новой серии**. Дальше работа идёт через props (как сейчас, но с нормальным UI). Это **не медленнее** текущего процесса, а быстрее (без папок и JSON руками).

## Шаг 2. Движок шаблона (canvas — опционально, путь B)

**По умолчанию (путь A):** шаг 2 **пропускаем** — используем существующий `green-plate-intro` + `cards[]`.

**Путь B (позже):** один универсальный шаблон `canvas-from-css`.

**Как он работает:**  
Вместо `cards[]` с жёсткой структурой — список **компонентов** на кадре:

- **text** — текст в прямоугольнике (позиция, размер, цвет, шрифт);
- **image** — картинка в прямоугольнике;
- **rect** — цветная плашка/фон.

Каждый кадр карусели = один «frame» 1080×1350. Remotion рисует компоненты по координатам `x, y, w, h`.

**Зачем:**  
Любой макет из CSS/AI становится набором блоков, а не новым React-файлом на каждый продукт.

**Готово когда:** есть тестовый `content.json` с 2–3 блоками → Run Render даёт PNG/MP4 без старого `green-plate-intro`.

## Шаг 3. Редактор props на главной (НЕ полная Figma)

**Важно:** Remotion уже работает через **input props**. У нас цепочка уже есть:

```
content.json  +  mapping.json  →  resolveRenderProps()  →  props  →  template.tsx  →  MP4
```

Шаблон читает `props.card1.title`, `props.card1.background` и т.д. — это и есть «встроенные пропсы» Remotion. **Новый движок с нуля не нужен** — нужен удобный UI поверх `content.json`.

**Что делаем (упрощённо):**  
Переносим и улучшаем то, что уже есть на `_dev` (`mvp-cards-editor.js`):

1. **Табы Card 1…7** — выбор карточки серии.
2. **Форма полей** — автоматически из `content.example.json` / mapping: текст, цвета, картинка (upload, не путь текстом).
3. **Превью** — `mvp-card-preview.js` (HTML), обновляется при правке.
4. **Run Render** — тот же `/api/render`, передаём `content` + `mapping` из шаблона.

**НЕ делаем в MVP шага 3:**
- отдельный canvas с drag-and-drop слоёв;
- свой Inspector с x/y/w/h для каждого блока (это только если перейдём на canvas-модель в шаге 2).

**Два пути (решить до кода):**

| Путь | Шаг 2 | Шаг 3 | Когда |
|------|-------|-------|-------|
| **A — быстрый** | оставить `green-plate-intro` + `cards[]` | props-редактор на главной | 1–2 недели, lavash/dolma как сейчас |
| **B — canvas** | новый `canvas-from-css` | редактор `components[]` | дольше, для новых серий из CSS |

**Рекомендация:** начать с **пути A** (props), шаг 2 canvas — только когда понадобится новая серия не из hello/quote/brand.

**Готово когда:** на главной выбрал lavash → поменял текст и цвет на Card 3 → превью обновилось → MP4 совпадает.

## Шаг 4. Сохранение и загрузка контента (API)

**Что делаем:**  
Studio должна **сохранять** правки на диск, а не только в памяти браузера.

**Новые запросы:**
- `GET /api/templates/:id/canvas` — отдать `content.json` + `schema.json` шаблона;
- `PATCH /api/templates/:id/canvas` — записать обновлённый контент после правок в Studio.

**Зачем:**  
Перезагрузил страницу — всё на месте. Можно рендерить на сервере то же самое, что видишь в UI.

**Готово когда:** поменял текст в Studio → F5 → текст остался; рендер использует сохранённый файл.

## Шаг 5. Парсер CSS (без нейросети)

**Что делаем:**  
Программа читает `.css` файл и вытаскивает **факты**: селекторы, `position`, `width/height`, `color`, `font-size`, CSS-переменные `--accent` и т.д.

**Инструмент:** библиотека `postcss` в Node.

**Зачем:**  
Нейросеть не должна угадывать пиксели — числа берём из CSS точно. AI только **называет** и **группирует** блоки.

**Готово когда:** на вход CSS lavash card 1 → на выход JSON со списком CSS-правил (промежуточный формат), без ещё Remotion.

## Шаг 6. Нейросеть + кнопка «Import CSS»

**Что делаем:**  
1. Берём результат шага 5 (разобранный CSS).  
2. Отправляем в LLM (OpenAI или Claude) с промптом:  
   «Собери из этого именованные компоненты: type, name, box, style. Тексты оставь пустыми.»  
3. Получаем `content.json` + `schema.json` и создаём новую папку шаблона.

**UI:** на странице Import — поле для CSS, имя шаблона, кнопка **Import** → редирект в Studio с новым шаблоном.

**Зачем:**  
Вместо ручного набивания 20 блоков — загрузил CSS из Figma Dev Mode, подправил 10% в Studio.

**Важно:**  
Первый раз будет **черновик**, не идеальная копия макета. Тексты вы всё равно пишете сами.

**Готово когда:** вставил CSS одной карточки → в Studio появились слои с примерными позициями и цветами.

## Что НЕ входит в эти 7 шагов (потом)

- Перетаскивание блоков мышью на холсте (только поля x/y/w/h);
- HTML вместе с CSS;
- Глобальные theme-переменные одной кнопкой;
- Деплой на VPS (отдельно, по запросу).
